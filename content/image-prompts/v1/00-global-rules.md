# Global Image Generation Rules V1

이 파일은 사진 분야에만 종속되지 않는 상위 규칙이다. 향후 플랫폼이 뷰티, 교육, 헬스, 커머스 등 다른 산업으로 확장돼도 그대로 유지하고 산업별 규칙을 하위에 추가한다.

## GLOBAL-IMG-001 — Context first

이미지 생성 전에 반드시 해당 슬롯의 챕터 제목, 섹션 제목, 본문 설명, 카드 제목, 강조문장, CTA 또는 지표를 읽는다. 단순 카테고리 키워드만 보고 이미지를 만들지 않는다.

이미지는 주변 문장을 보조해야 한다. 예를 들어 본문이 ‘반복 주문 구조’를 설명하는데 단순히 카메라를 든 사람만 보여주는 것은 부적합하다.

## GLOBAL-IMG-002 — 한 이미지, 한 역할

모든 슬롯은 다음 중 하나의 1차 역할을 갖는다.

- 실제 과정을 설명
- 목표 결과물을 보여줌
- 해당 챕터의 환경과 맥락을 설정
- 실제 제품/자료를 정확히 식별
- 외부 이미지 실패 시 안전한 fallback 제공

정보 역할이 없는 장식 이미지는 생성하지 않는다.

## GLOBAL-IMG-003 — 반복 금지

관련 없는 슬롯끼리 같은 장면, 같은 사람, 같은 카메라 앵글, 같은 소품 배치, 같은 제품을 재사용하지 않는다.

같은 챕터 내에서는 색감과 촬영 언어를 맞출 수 있지만, 각 슬롯은 한눈에 다른 내용을 설명해야 한다.

## GLOBAL-IMG-004 — 기본 스타일

기본값은 사실적인 editorial photography 또는 realistic commercial photography다.

금지:
- 명백한 AI 질감
- 과한 HDR
- 플라스틱 피부
- 손가락/손 형태 오류
- 중복된 물체
- 물리적으로 말이 안 되는 반사
- 이유 없는 시네마틱 연무
- 의미 없이 강한 teal/orange grading

## GLOBAL-IMG-005 — 사실성이 필요한 대상

특정 실제 제품, UI, 장소, 규정, 브랜드 오브젝트처럼 식별 정확도가 중요한 슬롯은 `reference_required`로 분류한다.

신뢰할 수 있는 참조 없이 실제 제품을 비슷하게 상상해서 생성하는 것은 금지한다.

## GLOBAL-IMG-006 — 이미지 안의 텍스트

생성 이미지 안에 읽어야 하는 문장을 넣지 않는다. 가격, 법적 문구, 차트 수치, UI 라벨, 파일명, 로고 등의 정보는 HTML이 담당한다.

화면이 필요한 장면은 구조만 보이고 텍스트는 읽히지 않는 수준으로 처리한다.

## GLOBAL-IMG-007 — 사람

사람은 자연스러운 표정과 자세를 사용한다. 과장된 광고 표정이나 전형적인 스톡사진 포즈를 피한다.

한국 사용자에게 실제 업무 환경을 설명하는 장면이라면 한국의 사무실, 카페, 스튜디오, 소규모 사업장과 자연스럽게 맞는 인물을 우선한다. 사람 자체가 필요하지 않은 장면에는 억지로 인물을 넣지 않는다.

## GLOBAL-IMG-008 — UI crop 우선

프롬프트는 최종 CSS crop을 기준으로 작성한다.

- `object-fit:cover` 슬롯은 주요 피사체를 안전영역 안에 둔다.
- 텍스트 오버레이가 있는 히어로는 카피가 올라갈 영역을 복잡하게 만들지 않는다.
- 모바일 카드에서 인지가 어려운 작은 디테일을 중심 주제로 삼지 않는다.

## GLOBAL-IMG-009 — 시리즈 일관성

같은 시리즈는 대비, 화이트밸런스, 현실감, 카메라 언어를 공유한다. 그러나 장면 자체는 복제하지 않는다.

## GLOBAL-IMG-010 — 모바일 가독성

작은 화면에서도 무엇을 보여주는 이미지인지 즉시 알아볼 수 있어야 한다. 한 장면에 주제가 너무 많으면 실패다.

핵심 의미를 미세한 색 차이만으로 전달하지 않는다.

## GLOBAL-IMG-011 — 출력 형식

프로덕션 기본 형식은 WebP다.

권장값:
- 메인/챕터 히어로: long edge 1600px 이상, 목표 280KB 이하
- 일반 카드: long edge 1200px 이상, 목표 160KB 이하
- 제품 식별 카드: 1000px square 이상, 목표 140KB 이하
- 큰 레슨 이미지: long edge 1400px 이상, 목표 200KB 이하
- WebP quality: 대체로 80~86 범위에서 육안 검수
- 불필요한 metadata 제거

생성기는 PNG/JPEG를 출력해도 되지만 최종 배포 파일은 지정된 경로의 WebP로 변환한다.

## GLOBAL-IMG-012 — 파일명과 경로

파일명과 경로는 생성 시 임의로 만들지 않는다. `manifest.json`과 `public/assets/image-slots-v1.js`에 지정된 경로가 유일한 기준이다.

## GLOBAL-IMG-013 — source class

- `generate`: 새 contextual asset 생성
- `reference_required`: 정확한 참조가 있을 때만 생성/정규화
- `preserve_external`: 실제 OG/thumbnail 등 원문 자산을 그대로 사용
- `fallback_generate`: 외부 이미지가 없을 때만 사용

## GLOBAL-IMG-014 — 생성 성공 ≠ 승인

아래를 모두 통과해야 `ready:true`가 된다.

1. 본문 맥락 일치
2. 실제 UI crop 적합
3. 현실감
4. 다른 슬롯과 중복되지 않음
5. 기술 품질
6. WebP 용량
7. 라이트/다크 UI에서 카드 경계와 이미지가 자연스러움

## GLOBAL-IMG-015 — 다른 산업으로 확장할 때

상위 규칙은 유지한다. 새 산업은 `industry-<name>-rules.md`를 추가한다. 특정 산업 때문에 상위 규칙을 느슨하게 바꾸지 않는다.

## GLOBAL-IMG-016 — 배치의 의미

배치 생성은 여러 슬롯을 한 개의 합성 이미지로 만드는 것이 아니다.

- 한 번의 사용자 지시에서 여러 슬롯을 처리할 수 있다.
- 실제 생성은 **슬롯별 독립 generation call**을 여러 번 연속 수행한다.
- 각 슬롯은 별도 최종 파일을 가진다.
- `n>1` 또는 다중 장면을 한 호출에 넣었을 때 dashboard, collage, contact sheet, infographic으로 합쳐질 가능성이 있으면 사용하지 않는다.
- 사용자는 슬롯마다 다시 지시할 필요가 없다. 작업자는 같은 턴/작업 흐름에서 다음 슬롯으로 자동 진행한다.

## GLOBAL-IMG-017 — 즉시 실패 판정

다음 중 하나라도 나타나면 해당 산출물은 **자동 QA 실패**다.

- dashboard, admin screen, progress report, infographic, presentation slide
- contact sheet, mood board, comparison grid, collage
- 한 캔버스에 여러 슬롯/여러 완성 이미지를 배치
- slot id, 파일명, 적용 상태, 진행률, Git/Drive/Cloudflare 정보가 이미지 안에 표현됨
- 생성 작업 자체를 설명하는 메타 이미지
- 프롬프트와 무관한 웹사이트/앱 UI
- 읽을 수 있는 가짜 문구가 시각적 핵심을 차지함
- 요구한 단일 실사 장면 대신 여러 장면이 카드 형태로 분할됨

이 실패 결과는 production asset으로 절대 사용하지 않는다.

## GLOBAL-IMG-018 — 실패 시 자동 재시도

실패한 슬롯은 사용자에게 다시 지시를 요구하지 않고 다음 순서로 자동 재시도한다.

1. 실패 이미지를 폐기한다.
2. 슬롯의 원래 prompt/body context는 유지한다.
3. 생성 입력을 해당 슬롯 하나의 장면만 남기도록 축약한다.
4. `single standalone photograph`, `one scene only`, `no text`, `no UI`, `no collage`, `no dashboard` 제약을 명시한다.
5. 독립 generation call로 다시 생성한다.
6. 같은 유형의 context-bleed 실패가 연속 2회 발생하면 텍스트-only 재시도를 중단하고 **검증된 실사 시각 앵커 기반 편집 생성**으로 전환한다.
7. 시각 앵커 기반 편집도 실패하면 해당 슬롯을 `qa_failed`로 기록하고 나머지 배치를 계속 진행한다.
8. 실패 슬롯 때문에 성공한 다른 슬롯의 WebP/Git/Drive 적용을 막지 않는다.

## GLOBAL-IMG-019 — 실패 결과의 상태 오염 금지

QA 실패 산출물은 다음 어디에도 반영하지 않는다.

- `public/assets/images/generated/...`
- Google Drive `Generated WebP`
- manifest/runtime `ready:true`
- Prompt Queue `applied`
- applied-status의 성공 슬롯 목록

필요하면 Prompt Queue 상태만 `qa_failed`로 남기고 실패 사유를 기록한다.

## GLOBAL-IMG-020 — 정상 결과의 필수 형태

정상 결과는 다음 조건을 **동시에** 만족한다.

- 최종 슬롯 1개에 대응하는 독립 이미지 파일 1개
- 한 개의 연속된 물리적 장면 또는 한 개의 완성 결과물
- HTML 없이도 이미지의 1차 의미를 1~2초 안에 이해할 수 있음
- 실사 슬롯은 실제 촬영 사진처럼 보여야 하며 보고서/설명판/웹페이지 캡처처럼 보이지 않음
- 슬롯 prompt의 핵심 피사체가 가장 먼저 보임
- 이미지 자체에 작업 진행 상황, 파일 경로, 적용 여부, 생성 규칙을 설명하지 않음
- 카드 crop 후에도 핵심 피사체와 행동이 남음
- 같은 배치의 다른 이미지와 구도·피사체·역할이 명확히 구분됨

정상 예시:
- 음식 슬롯: 실제 매장에서 대표 메뉴 한 접시가 주인공인 사진
- 프로필 슬롯: 사무실에서 대표 1명이 주인공인 비즈니스 초상
- 제품 슬롯: 단일 제품 또는 일관된 한 브랜드 세트가 주인공인 완성 제품사진
- 작업환경 슬롯: 하나의 실제 촬영 세팅을 보여주는 BTS 사진
- 리터칭 슬롯: 한 명의 작업자가 한 개의 모니터/태블릿에서 한 종류의 보정을 수행하는 현장 사진

## GLOBAL-IMG-021 — 시각 앵커 기반 회복 생성

대화 맥락 오염으로 메타 이미지가 반복될 때는 검증된 실사 이미지 또는 해당 슬롯과 가장 가까운 정상 자산을 **시각 앵커**로 사용한다.

규칙:
- 앵커는 정상 실사 자산이어야 한다. dashboard/collage는 앵커로 사용하지 않는다.
- 앵커의 전체 복제보다 슬롯에 필요한 피사체·빛·현실감·공간 언어만 유지한다.
- 필요 없는 인물/장비/텍스트는 제거하고 슬롯 목적에 맞게 재구성한다.
- 최종 결과는 여전히 독립 이미지 한 장이어야 한다.
- 앵커 기반 편집은 기존 슬롯을 덮어쓰는 것이 아니라 새 슬롯 자산을 만드는 방식으로 사용한다.

## GLOBAL-IMG-022 — 배치 진행 중 사용자 재지시 금지

사용자가 배치 진행을 지시하면 작업자는 슬롯마다 확인을 요구하지 않는다.

- 성공 슬롯은 자동으로 다음 단계(WebP → Drive → Git → ready/applied)로 진행한다.
- 실패 슬롯은 자동 재시도/시각 앵커 회복 규칙을 적용한다.
- 개별 실패가 있어도 다음 슬롯을 계속 생성한다.
- 배치가 끝난 뒤 성공/실패/적용 상태를 한 번에 보고한다.

## 프롬프트 조립 순서

실제 생성 입력은 다음 순서로 해석한다.

`GLOBAL RULES → INDUSTRY RULES → SLOT CONTEXT → SLOT PROMPT → AVOID LIST → OUTPUT/CROP REQUIREMENTS`
