# 03. AI Writing and Review Contract

이 문서는 관리자 Block Editor에서 AI가 산업 페이지의 초안을 작성하거나 기존 내용을 보완할 때 지켜야 할 작업 순서를 정의한다.

## AI-EDIT-001 — 구조를 임의로 결정하지 않는다

관리자가 산업 분야, 페이지 목적, block type, block 순서, 기본 방향을 정했다면 AI는 그 구조를 먼저 존중한다.

AI가 할 일:
- 필요한 세부 내용 조사
- block 목적에 맞는 초안 작성
- 중복/누락 검토
- 사실과 출처 확인
- 문장 정리

AI가 기본적으로 하지 않을 일:
- 승인된 block을 임의 삭제
- 레이아웃을 다른 타입으로 변경
- 관리자가 정한 핵심 방향 변경
- 사용자 작성 내용을 동의 없이 덮어쓰기

구조적으로 다른 block이 더 적합하다고 판단하면 수정하지 말고 제안 상태로 표시한다.

## AI-EDIT-002 — 입력 계약

페이지 전체 초안을 만들기 전 최소 다음 정보를 읽는다.

- industry/pack id
- page brief
- 대상 사용자
- 목표/범위
- 현재 block 배열과 순서
- 각 block의 editorialProfile
- 각 block의 referenceProfile
- 사용자 작성/잠금 필드
- 현재 데이터와 출처

정보가 비어 있어도 추측으로 중요한 사실을 채우지 않는다. 조사 가능한 것은 조사하고, 결정이 필요한 것은 `needs_decision` 상태로 남긴다.

## AI-EDIT-003 — 사실 잠금

초안 생성 전에 입력을 다음으로 구분한다.

- `fact_locked`: 사실/수치/고유명사. 표현만 다듬을 수 있고 값은 변경 금지
- `user_locked`: 사용자 작성 문장. 변경 금지
- `editable`: AI가 구조 안에서 작성/수정 가능
- `needs_verification`: 최신 출처 확인 전 확정 금지
- `needs_decision`: 사용자 기획 결정이 필요

문장 품질 작업과 사실 수정 작업을 한 번에 섞지 않는다.

## AI-EDIT-004 — 신규 초안

새 block의 초안은 다음 순서로 만든다.

1. block 목적 확인
2. 해당 editorialProfile 읽기
3. 필요한 사실/수치/출처 식별
4. 필요한 경우 최신 자료 조사
5. 제목/본문/항목/수치 초안 작성
6. 같은 페이지의 앞뒤 block과 내용 중복 확인
7. 사용자가 다음에 무엇을 이해하거나 결정할 수 있는지 확인

페이지 전체를 한 번에 장문의 글로 생성한 뒤 임의로 잘라 block에 넣지 않는다.

## AI-EDIT-005 — 기존 내용 보완

기존 문장을 수정할 때는 먼저 수정 이유를 분류한다.

- `clarity`: 이해하기 어려움
- `specificity`: 추상적임
- `redundancy`: 반복됨
- `tone`: AI식/번역투/부자연스러움
- `accuracy`: 사실 확인 필요
- `freshness`: 오래된 정보
- `structure`: 정보 순서가 나쁨

문제가 없는 문장은 유지한다.

## AI-EDIT-006 — 사용자 수정 모드

필드별 AI 수정 권한:

- `full`: 내용과 표현 수정 가능. 단 fact lock은 유지
- `wording_only`: 의미/사실/구조는 유지하고 표현만 수정
- `fact_check_only`: 문장은 변경하지 않고 사실 검증 결과만 표시
- `locked`: 읽기만 가능

관리자 UI에서 이 상태가 보여야 한다.

## AI-EDIT-007 — 조사와 출처

시점에 따라 바뀔 가능성이 있는 정보는 발행 전에 최신 확인이 필요하다.

대표 대상:
- 가격/단가
- 지원사업
- 법률/규제
- 세금
- 교육 제도
- 제품 사양/판매 상태
- 플랫폼 정책
- 광고/수익 정책
- 시장 데이터

가능하면 공식 기관, 제조사, 원문 통계, 1차 출처를 우선한다.

출처를 찾지 못한 사실은 확정형 문장으로 만들지 않는다.

## AI-EDIT-008 — 출처와 문장 연결

출처를 페이지 끝에만 모으지 않는다.

중요 수치나 제도 설명은 해당 block의 evidence field와 연결한다.

권장 evidence 데이터:
- source title
- publisher/organization
- URL
- published_at
- checked_at
- supports: 어떤 claim을 뒷받침하는지

## AI-EDIT-009 — 페이지 전체 검토

개별 block 초안 뒤 전체 페이지를 다시 읽는다.

검토 항목:
- 같은 설명 반복
- 앞뒤 논리 충돌
- 난이도 급변
- 빠진 핵심 단계
- 숫자 단위/기준 불일치
- 같은 용어의 다른 이름 사용
- 사용자가 실제로 행동할 수 없는 추상 조언
- 과도한 block 수
- 중요한 내용이 잘못된 block type에 들어간 경우

구조 변경이 필요하면 자동 적용보다 제안 상태를 우선한다.

## AI-EDIT-010 — 한국어 품질 검수 순서

사실과 구조가 안정된 뒤 문장을 검수한다.

1. 프로젝트 voice 원칙
2. AI 티/번역투/과윤문 점검
3. 문법/맞춤법/띄어쓰기
4. 용어/수치/형식 일관성
5. 모바일/PC 줄바꿈과 정보 밀도

외부 reference는 보조 검사 관점으로 사용한다.

## AI-EDIT-011 — 발행 상태

AI 생성 결과는 즉시 production에 공개하지 않는다.

권장 상태:
- `draft`
- `ai_reviewed`
- `fact_checked`
- `human_reviewed`
- `ready_to_publish`
- `published`
- `needs_update`

최소 `human_reviewed` 전에는 자동 publish하지 않는다.

## AI-EDIT-012 — 변경 이력

AI가 기존 published 내용을 수정하면 새 revision을 만든다.

저장할 정보:
- 이전 값
- 새 값
- 변경 이유
- AI/사용자 구분
- 검증된 출처
- 수정 시각

관리자는 이전 revision으로 되돌릴 수 있어야 한다.

## AI-EDIT-013 — SEO/GEO

SEO/GEO는 본문이 안정된 다음 생성한다.

AI는 실제 페이지에 없는 사실을 meta/schema/FAQ에 추가하지 않는다.

페이지의 핵심 주제, 대상, 실제 구성, 출처, 작성/검토일을 기반으로 metadata를 만든다.

## AI-EDIT-014 — 실패 처리

AI가 충분한 근거를 확보하지 못하면 빈칸을 억지로 채우지 않는다.

표시 예:
- `출처 확인 필요`
- `가격 기준일 필요`
- `사용자 결정 필요`
- `산업 전문가 검토 권장`

미완료 상태를 그럴듯한 확정 문장으로 감추는 것보다 낫다.
