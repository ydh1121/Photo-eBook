# 02. Block Copy Profiles

Block Registry의 각 UI block은 이 문서의 `editorialProfile` 중 하나를 연결한다. 같은 페이지 안에서도 블록의 목적이 다르면 제목, 본문, 수치, CTA를 같은 형식으로 쓰지 않는다.

## `hero`

목적: 페이지가 누구를 위한 것이고 어디까지 안내하는지 첫 화면에서 이해시킨다.

권장 필드:
- eyebrow: 분야/가이드 성격을 짧게 표시
- title: 핵심 주제
- description: 대상 + 목표 + 범위를 1~3문장
- facts: 페이지를 이해하는 데 실제로 필요한 핵심 수치/조건만

규칙:
- 제목에 설명을 모두 몰아넣지 않는다.
- 분야명을 제목과 설명에서 반복하지 않는다.
- 근거 없는 성과 약속을 하지 않는다.
- fact card는 서로 다른 판단 정보를 보여준다.

## `section-heading`

목적: 다음 블록 묶음에서 무엇을 보게 되는지 안내한다.

규칙:
- eyebrow는 분류, title은 핵심 판단, description은 이유나 보는 방법을 담당한다.
- 세 필드가 같은 문장을 반복하지 않는다.
- 제목은 가능한 한 한 가지 메시지만 가진다.

## `rich-text`

목적: 카드로 쪼갤 필요가 없는 설명과 맥락을 전달한다.

규칙:
- 한 단락에 주제 하나.
- 초보자에게 낯선 용어는 기능부터 설명.
- 중요한 판단 기준이 3개 이상 병렬이면 목록/체크리스트/비교 블록 전환을 검토한다.
- 긴 본문을 카드 여러 개로 장식하기 위해 임의 분절하지 않는다.

## `process`

목적: 해야 할 일의 순서와 선후관계를 보여준다.

규칙:
- 단계는 행동으로 시작한다.
- 한 단계에 서로 다른 행동을 과도하게 묶지 않는다.
- 이전 단계가 다음 단계에 왜 필요한지 흐름이 보여야 한다.
- 모든 단계의 문장 구조를 억지로 동일하게 만들 필요는 없지만 동작 단위는 일관되게 쓴다.

## `ranking`

목적: 우선순위를 보여준다.

규칙:
- 순위에는 비교 기준이 있어야 한다.
- `1위`라는 표현만으로 우월성을 암시하지 않는다.
- 기준이 상황별로 달라지면 절대 순위 대신 추천 조건을 표시한다.
- 수치 근거가 있으면 출처/확인일과 연결한다.

## `comparison`

목적: 사용자가 선택할 수 있도록 차이를 같은 기준으로 보여준다.

규칙:
- 비교 대상보다 먼저 비교 기준을 설계한다.
- 각 항목은 가능한 한 같은 필드 구조를 가진다.
- 장점만 쓰지 않는다.
- 가격, 시간, 진입 난이도, 반복 수요, 필요한 기술처럼 실제 선택에 필요한 차이를 우선한다.
- `좋음/나쁨` 같은 평가어는 기준 없이 사용하지 않는다.

## `pros-cons`

목적: 하나의 선택지에서 얻는 것과 감수해야 할 것을 같이 보여준다.

규칙:
- 장점과 단점을 같은 수준의 구체성으로 쓴다.
- 단점을 형식적으로 한 줄 넣고 사실상 광고 문구로 만들지 않는다.
- 조건에 따라 달라지는 사항은 조건을 함께 표시한다.

## `metrics`

목적: 수치로 규모, 비용, 목표, 계산 구조를 이해시킨다.

규칙:
- 숫자만 크게 보여주지 않는다.
- 숫자의 단위와 의미를 붙인다.
- 추정치면 추정이라고 표시한다.
- 기준 시점, 산식, 전제조건, 출처 중 필요한 항목을 함께 둔다.
- 여러 수치를 합산하거나 비율로 계산하면 사용자가 계산 흐름을 확인할 수 있어야 한다.

## `calculator`

목적: 사용자가 자신의 조건을 넣어 결과를 계산한다.

규칙:
- 입력값 의미와 단위를 명확하게 표시한다.
- 기본값은 예시인지 권장값인지 구분한다.
- 결과값에는 계산식/전제를 확인할 수 있는 설명을 제공한다.
- 법률·세금·대출처럼 결과가 확정값이 아닌 경우 한계를 표시한다.

## `checklist`

목적: 빠뜨리지 않고 확인하거나 준비하게 한다.

규칙:
- 항목 하나에 확인사항 하나.
- 추상적인 `잘 준비했는가` 대신 확인 가능한 상태를 쓴다.
- 순서가 중요한 체크리스트라면 process로 전환한다.
- 완료 여부가 아니라 질문형 점검에 가까우면 문장 톤을 통일한다.

## `callout`

목적: 본문 중 중요한 기준이나 예외를 짧게 강조한다.

규칙:
- 이미 본문에서 강조한 내용을 다시 반복하지 않는다.
- 한 callout에는 핵심 하나.
- `중요`, `TIP`, `핵심` 같은 레이블을 남발하지 않는다.
- 레이블은 실제 성격을 설명할 때만 사용한다.

## `warning`

목적: 비용, 법적 위험, 오해, 실패 가능성처럼 행동을 멈추거나 다시 확인해야 할 조건을 전달한다.

규칙:
- 불안을 과장하지 않는다.
- 무엇이 위험한지와 어떤 행동을 해야 하는지를 같이 쓴다.
- 법률/의료/재정 등 고위험 정보는 최신 출처와 기준 시점을 요구한다.

## `case-study`

목적: 실제 사례나 자체 기획 사례를 통해 과정과 결과를 보여준다.

권장 흐름:
`사례 성격 → 목적 → 조건 → 과정 → 산출물/결과 → 배운 점`

규칙:
- 실제 고객 사례와 자체 기획 사례를 구분한다.
- 결과만 나열하지 않고 어떤 조건에서 나온 결과인지 보여준다.
- 사례가 일반적인 결과를 보장하는 것처럼 쓰지 않는다.

## `portfolio`

목적: 초보자가 어떤 결과물을 준비해야 하는지 구체적으로 보여준다.

규칙:
- `그럴듯하게 보이기`보다 사용 목적과 산출물을 설명한다.
- 자체 기획 촬영/작업임을 숨기지 않는다.
- 결과 이미지가 있으면 준비/과정/납품 구성과 연결한다.

## `product-tool`

목적: 장비, 소프트웨어, 재료, 서비스 등 실제 도구를 선택하게 한다.

규칙:
- 제품명을 과도하게 반복하지 않는다.
- 가격은 기준 시점과 판매처/출처 조건을 고려한다.
- 추천 이유를 기능과 사용 조건으로 설명한다.
- 제휴/광고 여부가 있다면 별도 표시한다.
- 실제 제품 사양을 AI가 추정해서 채우지 않는다.

## `roadmap`

목적: 일정 기간 동안 목표와 행동의 변화를 보여준다.

규칙:
- 시간 구간마다 목표와 행동이 달라야 한다.
- `성장하기`, `브랜딩하기`처럼 검증하기 어려운 단계명보다 구체적인 상태를 쓴다.
- 기간은 절대 보장값으로 쓰지 않는다.
- 단계 사이 의존관계가 있으면 표시한다.

## `timeline`

목적: 시간순 사건, 절차, 일정, 경력 흐름을 보여준다.

규칙:
- 시간 표기 형식을 통일한다.
- 시점이 없는 항목을 억지로 timeline에 넣지 않는다.
- 현재/예정/완료 상태를 구분한다.

## `script-copy`

목적: 사용자가 실제로 복사해 쓸 메시지, 문의문, 견적 안내 등의 초안을 제공한다.

규칙:
- 실제 상황에 바로 붙여넣을 수 있을 정도로 구체적이어야 한다.
- 사용자가 바꿔야 할 변수는 명확하게 표시한다.
- 상대를 속이거나 경력/성과를 과장하는 문구를 만들지 않는다.
- 복사 버튼의 레이블은 짧게 쓴다.

## `media-rail`

목적: 이미지·영상·작업 예시를 빠르게 훑는다.

규칙:
- 카드 제목만 읽어도 서로 다른 항목이라는 것이 보여야 한다.
- 설명은 이미지/영상에서 보이지 않는 맥락을 보완한다.
- 같은 설명을 모든 카드에 반복하지 않는다.
- 외부 콘텐츠는 출처/작성자/플랫폼 정보를 실제 데이터와 연결한다.

## `image-copy-split`

목적: 하나의 핵심 장면이나 결과물과 설명을 함께 보여준다.

규칙:
- 이미지가 단순 장식이면 이 블록을 쓰지 않는다.
- 설명은 이미지에서 사용자가 봐야 할 부분을 알려준다.
- alt는 이미지의 기능과 맥락을 반영한다.

## `gallery`

목적: 같은 주제의 여러 결과물을 비교하거나 순서대로 본다.

규칙:
- 이미지마다 필요한 경우 짧은 caption을 둔다.
- 서로 다른 정보 역할이 없다면 중복 이미지를 늘리지 않는다.
- before/after는 어느 쪽이 전/후인지 명확히 표시한다.

## `faq`

목적: 사용자가 실제로 반복해서 궁금해하는 질문을 빠르게 해결한다.

규칙:
- 질문은 검색어를 억지로 삽입한 문장보다 실제 사용자 질문처럼 쓴다.
- 답변 첫 문장에서 핵심을 먼저 말한다.
- 본문 전체를 FAQ로 복제하지 않는다.
- 시점에 따라 바뀌는 답은 기준일/출처를 포함한다.

## `quote-expert`

목적: 인터뷰, 전문가 의견, 실제 발언을 맥락과 함께 보여준다.

규칙:
- 직접 인용과 요약을 구분한다.
- 인용을 임의로 수정하지 않는다.
- 발언자와 출처를 표시한다.
- AI가 존재하지 않는 전문가 발언을 생성하지 않는다.

## `source-evidence`

목적: 주장과 숫자가 어디에서 왔는지 사용자가 확인할 수 있게 한다.

규칙:
- 링크만 쌓지 않고 어떤 사실을 뒷받침하는 출처인지 적는다.
- 기관/문서명, 확인일, 필요하면 발표일을 표시한다.
- 1차 출처를 우선한다.
- 오래된 출처가 현재 상태를 설명하는 것처럼 보이지 않게 한다.

## `cta`

목적: 다음 행동을 명확히 안내한다.

규칙:
- 버튼은 동작을 짧게 표시한다.
- 한 영역에 우선순위가 같은 CTA를 과도하게 두지 않는다.
- 외부 링크, 다운로드, 저장, 계산 등 실제 결과와 레이블이 일치해야 한다.

## `seo-geo`

목적: 검색엔진과 AI 검색이 페이지의 주제와 근거를 정확히 이해하도록 돕는다.

규칙:
- 검색어를 반복하기 위해 사람이 읽는 문장을 망가뜨리지 않는다.
- 페이지의 실제 내용과 다른 title/description/schema를 만들지 않는다.
- 중요한 정의, 비교, 수치에는 확인 가능한 출처를 연결한다.
- 작성/검토일, 실제 사례, 조사 방법처럼 신뢰도를 높이는 정보는 사실일 때만 표시한다.
- FAQ나 구조화데이터를 검색 노출만을 위해 본문에 없는 내용으로 생성하지 않는다.
